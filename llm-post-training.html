LLM Post-Training

One-line summary: SFT minimizes the forward KL divergence DKL(pdata ‖ πθ); RL minimizes the reverse KL divergence DKL(πθ ‖ p*).

1. SFT vs. RL: what's actually different

The cleanest way to distinguish them is by asking which distribution generates the training samples, and which direction of KL divergence gets minimized.

  • SFT trains on samples y drawn from a fixed data distribution. Minimizing the standard cross-entropy loss −log πθ(y|x) is equivalent to minimizing the forward KL divergence DKL(pdata ‖ πθ). SFT asks: what does the data distribution produce, and does the model cover it?
  • RL trains on samples y drawn from the policy itself, which a reward model then scores. KL-regularized RL corresponds to minimizing the reverse KL divergence DKL(πθ ‖ p*) against a reward-tilted target distribution p*. RL asks: what does the policy currently produce, and is that reasonable under the reward-tilted target?
Memory aid: SFT = data samples, model scores. RL = model samples, reward scores.

2. Policy gradient: from reward objective to parameter update

Reward function, following Lilian Weng's formula: the state-value function Vπ(s) represents the average reward you expect to get from state s. To find that average, you multiply the probability of taking an action by the payoff of that action, and sum them up.

The state-value function Vπ(s) is the average return expected from state s. That expectation averages over actions: multiply each action's probability by its expected future return and sum over actions.

Vπ(s) = Ea∼π[Qπ(s,a)] = Σa∈Aπ(a|s)Qπ(s,a)

The reward objective is:

J(θ) = Σs∈Sdπ(s)Vπ(s) = Σs∈Sdπ(s)Σa∈Aπθ(a|s)Qπ(s,a)

Here dπ(s) is the stationary distribution of the Markov chain for πθ — the on-policy state distribution under π: the probability of visiting state s while following πθ. (For simplicity, the parameter θ is often omitted from the subscript of π, d, and Q when the policy π is already present elsewhere in the expression — e.g. dπ and Qπ should be read as dπθ and Qπθ if written in full.) The policy-gradient theorem rewrites the gradient as:

∇θJ(θ) ∝ Σs∈Sdπ(s)Σa∈AQπ(s,a)∇θπθ(a|s)
∇θJ(θ) = Es∼dπ, a∼πθ[Qπ(s,a)∇θlog πθ(a|s)]
The policy-gradient algorithm is, at its core, just using gradient descent to maximize this reward.

Replacing Q with advantage gives:

Aπ(s,a) = Qπ(s,a) − Vπ(s)
∇θJ(θ) = E[Aπ(s,a)∇θlog πθ(a|s)]

More concretely, a sampled gradient contribution is:

ĝt = Ât∇θlog πθ(at|st)

The fundamental Monte Carlo policy-gradient update can also be written:

θt+1 = θt + α∇θlog πθ(at|st)Gt
  • θ: the policy-network parameters.
  • α: the learning rate.
  • ∇log πθ(at|st): the direction that increases the sampled action's log-probability.
  • Gt: the cumulative discounted return from time t to the end of the trajectory.

Policy gradient versus the gradient-descent optimizer

These are different layers of the training procedure. Gradient descent's parameter-update rule tells you, given the gradient, how to update the parameter: w_new = w_old + learning_rate × gradient. Optimizers built on top of gradient descent are mostly concerned with how to scale that gradient and modify the update rule.

  • The policy-gradient algorithm defines what loss you optimize and how you compute advantage / constrain policy movement.
  • The optimizer receives the resulting gradient and decides how to scale it and update the parameters — you still usually use Adam or AdamW underneath to update weights.

For supervised learning, the loss is directly differentiable:

Python prediction = model(x) loss = cross_entropy(prediction, label) gradient = ∇θ loss θ ← θ - learning_rate * gradient

The label is known, and the loss is directly computed.

For RL / policy gradient, the problem is harder:

Python policy samples action environment/reward model gives reward sampled action is discrete reward is not directly differentiable through sampling

So we need policy gradient:

increase probability of actions that got good reward decrease probability of actions that got bad reward

The basic policy-gradient form is:

gradient ≈ advantage × ∇θlog πθ(action|state)

Redrawn as a side-by-side comparison:

Supervised learning

Known label→Cross-entropy loss→Direct gradient
θ ← θ − learning_rate × ∇θloss

RL / policy gradient

Policy samples a discrete action→Environment or reward model scores it

The reward is not directly differentiable through discrete sampling, so the update increases probabilities of actions with positive advantage and decreases probabilities of actions with negative advantage.

gradient ≈ advantage × ∇θlog πθ(action|state)

Adam versus AdamW

The standard adaptive-optimizer update can be summarized as:

θt = θt−1 − γ(m̂t / (√v̂t + ε)) − ηλθt−1
  • θt: model parameters.
  • γ: learning rate.
  • m̂t and v̂t: bias-corrected moving averages of gradients and squared gradients.
  • ε: a small smoothing term that prevents division by zero.
  • λ: weight-decay rate.
  • η: schedule multiplier.

In Adam, L2 regularization is mixed into the gradient moments. In AdamW, weight decay is decoupled and subtracted directly from the weights, so decay does not depend on the gradient's history.

3. PPO, GRPO, and DPO at a glance

In all three methods, the policy is the LLM model we are fine-tuning. The difference is how training examples and learning signals are produced.

PPO. Given a prompt, the current policy model generates an answer, the reward model scores that answer, and PPO updates the policy to get higher reward. The loss maximizes reward, minus a KL penalty from the reference model, minus the expected reward from the value model.

GRPO. Given a prompt, generate multiple answers (answer 1, answer 2, answer 3, answer 4, …), score each answer, compare within the group, then do the RL update.

DPO. Each prompt comes with a chosen answer and a rejected answer. Use the chosen/rejected data to directly optimize preference, so that P(chosen answer) > P(rejected answer), relative to a reference model.

Redrawn as a side-by-side comparison:

PPO

Prompt→Policy generates one answer
Reward model scores it→Value model supplies a baseline
GAE advantages→Clipped policy update

Goal: maximize reward while penalizing drift from the reference model.

GRPO

Prompt→Generate a group of answers
Score every answer→Compare within the group
Group-relative advantages→Clipped policy update

Key difference: the group average replaces the learned value-model baseline.

DPO

Prompt→Chosen + rejected answers
Compare policy/reference log-ratios→Direct preference update

Goal: make P(chosen answer) > P(rejected answer), relative to a reference model.

No separately trained reward model or value model is required during optimization.

PPO: building the loss layer by layer

It's easiest to understand PPO's objective as a sequence of small fixes layered on top of the plain policy-gradient loss, each addressing a specific failure mode of the previous version.

Step 1. Start from loss = −advantage × log_prob(generated answer). If advantage > 0, minimizing the loss increases the log-probability of that answer — the model becomes more likely to generate it. If advantage < 0, the reverse. Advantage controls the direction and strength of every update.

Step 2. The problem with using log_prob(answer) directly is that if you update the model too aggressively in one step, the probability can change drastically and destroy prior knowledge. So instead, track the probability ratio between the new and old policy: ρ = pnew(answer)/pold(answer) = exp(log pnew − log pold). The loss becomes −advantage × ρ. If ρ = 1 the new model behaves exactly like the old one; if ρ = 1.2, it's 20% more likely to generate that answer than before.

Step 3. Add clipping to prevent destructive updates. PPO computes two candidate losses and takes the worse one (the max, which corresponds to the pessimistic/min objective on reward): Loss1 = −advantage × ρ, and Loss2 = −advantage × clip(ρ, 1−ε, 1+ε). Final Policy Loss = max(Loss1, Loss2). The practical effect is easiest to see as a small table:

AdvantageRatio conditionMeaningPolicy gradient?

Step 4. Combine the clipped policy loss with a KL penalty against the reference model to bound overall drift: Loss = max(−A×ρ, −A×clip(ρ, 1−ε, 1+ε)) + KL penalty. This needs four models in play at once — policy, reference, reward, and value.

What the value model is and how it is trained

The value model is used as a baseline for the reward. Because a reward is only known at the prompt/sequence level, you can't tell whether a given reward is good or bad without a baseline to compare it to — that's exactly how advantage is computed: return minus the value-model prediction.

advantage = return − value-model prediction
Is the value model trained during PPO, together with the policy model? Yes. The value model learns to predict the expected future KL-penalized reward from every token position. Architecturally, it is commonly a policy-like transformer with a scalar value head that produces V(s1), V(s2), …, V(sT) rather than vocabulary logits.

Sequence-level reward versus token-level PPO updates

Is the value model token-level while reward is prompt-level? Yes — in LLM PPO this is the key complication.

Usually the reward model gives a reward for the whole completion:

Prompt + generated answer → reward score Example: Final reward = 0.8

But PPO updates the policy at the token level:

token 1 probability token 2 probability token 3 probability ...

So we need token-level advantages Â₁, Â₂, Â₃, …, ÂT. Each token needs to know: did this token contribute to a better-than-expected final answer? Since PPO updates the policy at the token level but a scalar reward typically only exists at the sequence level, it needs a token-level advantage for every position. That's exactly what the value model and GAE are for — see RL Foundation for the full derivation.

Prompt + generated answer ─────────────────────────────→ final reward score = 0.8 token 1 token 2 token 3 ··· token T │ │ │ │ ▼ ▼ ▼ ▼ A₁ A₂ A₃ A_T Question for every token: Did this token contribute to a better-than-expected final answer?

In many RLHF settings, most tokens receive no external task reward. Instead, each token may receive a KL penalty, while the reward-model score arrives at the final token:

r1 = −β KL1,   r2 = −β KL2,   …,   rT = reward_model_score − β KLT

The direct Monte Carlo return from token t is:

Rt = rt + γrt+1 + γ2rt+2 + ⋯ + γT−trT

and the Monte Carlo return advantage is:

ÂtMC = Rt − V(st)

Why GAE is needed

GAE converts sparse or final rewards into smoother token-level advantage estimates. Instead of relying only on the full Monte Carlo return, it starts from the one-step TD residual:

δt = rt + γV(st+1) − V(st)

The TD residual is itself a one-step advantage estimate:

Ât(1) = δt

An n-step advantage can be expressed as a discounted sum of one-step TD residuals:

Ât(n) = Σl=0n−1 γlδt+l

GAE uses a λ-weighted combination of multi-step advantages:

ÂtGAE(γ,λ) = δt + (γλ)δt+1 + (γλ)2δt+2 + ⋯ + (γλ)T−tδT
ÂtGAE(γ,λ) = Σl=0T−t(γλ)lδt+l,   λ ∈ [0,1]

GAE propagates the final reward signal backward to earlier tokens while using the value model to reduce noise. Monte Carlo uses the true accumulated token rewards; GAE mixes observed token rewards with bootstrapped value estimates.

This maps onto two concrete training strategies. A pure Monte Carlo strategy scales the policy gradient using Â = γT−trT − V(st), where every single token inherits the same sequence-level blame or praise, and trains the critic by minimizing MSE directly against the full empirical outcome — zero bias, but extreme variance, since trajectory fluctuations heavily destabilize the gradient. A GAE strategy scales the policy gradient smoothly using ÂGAE, where the late-stage penalty or reward echo decays exponentially by (γλ)l, and trains the critic against the GAE-bootstrapped value targets instead — balanced variance (intermediate critic anchors intercept noise), at the cost of some controlled bias if the critic network is still undertrained.

Why PPO?

PPO is a policy-gradient algorithm from reinforcement learning. It's used in RLHF to train an LLM safely and efficiently.

  • PPO allows stable and constrained updates to the model.
  • It avoids drastic policy changes that could hurt performance (by clipping the update step).
  • It helps maintain a balance between exploration (trying new responses) and exploitation (using what it knows works well).

In LLMs:

  • The policy is the language model: it generates text (actions) based on input (state).
  • PPO updates the policy to prefer outputs that the reward model likes more.
  • It helps reduce toxicity, improve helpfulness, and avoid hallucination.

DPO: skipping the reward model entirely

DPO improves on PPO's complexity (four models, four moving pipelines) by using pairwise comparison data collected in advance (offline), bypassing the reward-modeling step, and optimizing the language model directly against preference data. The motivation: optimize the policy directly on preference pairs via a classification-style loss.

The dataset DPO needs has three parts per example:

  • prompt — the input x
  • chosen — the preferred response yw
  • rejected — the dispreferred response yl

DPO doesn't need any extra scoring data. It works directly from a chosen response yw and a rejected response yl, and maximizes the implicit reward model's scoring gap between them — i.e. it maximizes how much the chosen response's reward exceeds the rejected response's reward:

LDPO(πθ; πref) = −E(x,yw,yl)~D[log σ(β log(πθ(yw|x)/πref(yw|x)) − β log(πθ(yl|x)/πref(yl|x)))]

Walking through what minimizing this actually does: it's equivalent to maximizing the implicit rewards rw = log(πθ(yw|x)/πref(yw|x)) and rl = log(πref(yl|x)/πθ(yl|x)). For the preferred outcome yw, we want πθ(yw|x) to grow; for the dispreferred outcome yl, we want it to shrink. And the gradient adapts to how wrong the reference model already was: if πref(yw|x) was small, meaning the reference model failed to favor the good response, rw's coefficient becomes large; if πref(yl|x) was large, meaning the reference model failed to disfavor the bad response, rl's coefficient becomes large too. In short, DPO pushes hardest exactly where the reference model's preferences were most wrong — without ever training a separate reward or value model.

GRPO: trading the value model for group statistics

GRPO keeps PPO's clipped-ratio structure but removes the value model altogether. Instead of a learned baseline, it samples several responses to the same prompt and uses the group's own average reward as the baseline:

advantage = reward − group average reward

This sidesteps the memory and compute cost of training a separate critic, and the difficulty of accurately predicting token-prefix values for long LLM outputs — but it also means GRPO's advantage estimate is only as good as the diversity of the sampled group, which is exactly the property its later variants (DAPO among them) end up having to patch.

DAPO: patching GRPO's four failure modes

DAPO doesn't propose a new objective from scratch; it's a set of four targeted fixes to specific ways vanilla GRPO breaks down in practice, especially on long chain-of-thought training.

1. Clip-Higher — decoupling the clip bounds. PPO/GRPO's traditional clipping range is symmetric: ρt ∈ [1−ε, 1+ε] (e.g. [0.8, 1.2] at ε=0.2). That symmetry quietly caps how fast the model can reinforce rare-but-correct behavior: a rare, correct reasoning token with probability 0.01 under the old model can, even inside a fully correct response, only be pushed up to 0.01 × 1.2 = 0.012 in one update. The model therefore struggles to quickly reinforce newly discovered reasoning patterns, increasingly falls back on already-high-probability patterns, and can suffer entropy collapse or reduced exploration. DAPO decouples the bounds — ρt ∈ [1−εlow, 1+εhigh] with εhigh > εlow (e.g. 0.2 and 0.28, giving [0.8, 1.28]) — so the model stays cautious about suppressing existing behavior but is allowed a bigger jump when reinforcing a newly discovered correct one.

2. Dynamic Sampling — don't waste compute on zero-gradient groups. GRPO's advantage depends entirely on reward variation within a group of sampled responses to the same prompt. If all G responses to a prompt are correct (R1=…=RG=1) or all wrong (R1=…=RG=−1), every response's reward equals the group average, so every advantage is exactly zero and the group produces no usable policy gradient. As training progresses the model masters more and more easy prompts, so more and more groups collapse to accuracy=0 or accuracy=1, quietly wasting generation compute and shrinking the effective batch size. DAPO filters to keep only prompts with 0 < accuracy < 1 (some correct, some incorrect among the G samples), and keeps sampling fresh prompts until the batch is filled back up. The intuition: don't spend training signal on prompts the model has already mastered or still can't touch at all — spend it on prompts right at the model's current capability boundary, where some rollouts succeed and some fail.

3. Token-level policy gradient loss — stop underweighting long responses. Vanilla GRPO averages token loss within each response first, then averages across responses, so every response gets equal total weight regardless of length: Li = (1/|oi|) Σt Li,t, then LGRPO = (1/G) Σi Li. Concretely, if response A is 100 tokens and response B is 1,000 tokens, each gets ~50% of the total weight under response-level averaging — so each individual token in the short response ends up carrying roughly 10× the weight of each token in the long one. In long chain-of-thought training this causes two real problems: correct reasoning steps inside long correct answers get under-reinforced, and repetition, errors, and wasted reasoning inside long wrong answers get under-penalized. DAPO instead averages uniformly over every valid token in the whole training batch: LDAPO = ΣiΣt Li,t / Σi|oi|. With the same 100- vs. 1,000-token example (using a 900-token response B here), token-level weighting gives A ~10% of total weight and B ~90% — every reasoning token gets a comparable training signal regardless of which response it's in.

4. Overlong Reward Shaping — don't blindly punish truncation. Generation is capped at some max length (e.g. Lmax = 20,480 tokens); if the model hasn't finished by then, its output is force-truncated. A truncated response isn't necessarily a bad one — the reasoning so far might be basically correct, the model may simply have been mid-derivation, or the final answer just hadn't been emitted yet. Naively assigning truncated responses a strong negative reward teaches the model that the entire reasoning path was worthless, injecting noise and destabilizing training. DAPO offers two fixes: Overlong Filtering, which masks truncated samples out of the policy-gradient computation entirely rather than treating them as flatly wrong; and Soft Overlong Punishment, which ramps the length penalty up gradually as a response approaches Lmax (using a buffer zone Lcache) rather than applying a sudden, sharp penalty only once the cap is hit.
