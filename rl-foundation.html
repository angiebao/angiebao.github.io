RL Foundation

These notes focus on PPO first. They build from the policy-gradient objective to advantage estimation, temporal-difference learning, generalized advantage estimation, and value-model training in LLM reinforcement learning.

The big picture: where PPO fits in reinforcement learning

At the most general level, reinforcement learning asks an agent to learn behavior that maximizes expected cumulative reward. The agent interacts with an environment, takes actions, receives rewards, and updates its behavior so that higher-reward trajectories become more likely.

Objective: maximize J(θ) = Eτ∼πθ[R(τ)]

There is more than one way to pursue this objective. A useful working hierarchy is:

  1. Model-free reinforcement learning: learn behavior from experience without first learning an explicit model of the environment's transitions.
    • Value-based methods: learn values such as V(s) or Q(s,a) (expected future return after action a in state s), then derive behavior by choosing high-value actions. Examples include tabular Q-learning and Deep Q-Networks (DQN).
      Concrete example: in an Atari game, DQN estimates Q(screen, action) (expected future score after taking that action from that screen) for actions such as left, right, or fire, then usually chooses the action with the largest estimated Q-value (largest expected future return).
    • Policy-based methods: represent and optimize the policy directly. Examples include REINFORCE, TRPO, and PPO.
      Concrete example: a robot policy outputs a probability distribution over movements. After a successful trajectory, the update increases the probability of movements that contributed to the high return. In LLM post-training, each generated token is an action and PPO adjusts token probabilities according to estimated advantage.
      • Policy-only: update the policy using sampled returns without learning a separate critic. Vanilla REINFORCE is the clearest example.
      • Actor–critic: update the policy (actor) with help from a learned value function (critic). Examples include A2C, A3C, DDPG, TD3, SAC, and the usual implementation of PPO. The critic estimates how good the current state or action is; that estimate supplies a lower-variance learning signal for the actor.
  2. Model-based reinforcement learning: learn or use a model of the environment to predict what will happen, then plan or improve behavior using those predictions. Examples include Dyna-Q, Model Predictive Control (MPC), AlphaZero, and MuZero.
    Concrete example: before moving, a game-playing agent simulates several possible future action sequences, estimates their outcomes, and chooses the action whose simulated future looks best. MuZero learns the dynamics needed for planning without reconstructing every detail of the observation.

This hierarchy is intentionally practical rather than absolute. A model-based system may still contain value functions, policies, or actor–critic components inside its planning and learning loop.

These notes begin with the policy-gradient direction. In this direction, we estimate how changing the policy parameters would change expected reward, then construct a loss function whose gradient produces a useful policy update. PPO is one algorithm for making that update practical and stable; it is not the definition of reinforcement learning itself.

Other methods within the policy-gradient direction

Even after choosing policy-gradient optimization, PPO is not the only option:

  • REINFORCE: uses the complete Monte Carlo return Gt to scale ∇log π(at|st). For example, if a CartPole episode survives for a long time, all sampled actions in that successful trajectory are reinforced according to their returns. It is conceptually simple but often has high variance because the update waits for the actual trajectory outcome.
  • Actor–critic: learns a critic alongside the policy and uses the critic as a baseline or return estimator. For example, A2C or A3C updates the actor using an advantage such as Gt − V(st) while simultaneously training V(st) to predict returns. This usually reduces variance compared with pure REINFORCE.
  • TRPO (Trust Region Policy Optimization): maximizes a policy-improvement objective while explicitly constraining the average KL divergence between the old and new policies. In a locomotion task, this prevents one batch from changing the robot's gait so drastically that previously useful behavior is destroyed.
  • PPO (Proximal Policy Optimization): approximates the trust-region idea with a simpler clipped or KL-penalized objective. If an action's probability ratio moves outside the permitted range, clipping prevents that sample from continuing to push the policy too far. In LLM RLHF, this helps keep a policy update from moving token probabilities excessively far from the rollout policy in one optimization round.

So the hierarchy to keep in mind is: reinforcement learning → maximize expected reward → choose an optimization family → policy-gradient methods → choose a specific update rule such as REINFORCE, TRPO, or PPO. We focus on PPO first because it provides a useful path through the core ideas of policy gradients, advantage estimation, critics, TD learning, and GAE.

Policy-gradient terminology and algorithm examples in this section follow Lilian Weng's overview, “Policy Gradient Algorithms.”

From reward to policy gradient

The reward function is defined as an expectation over the states and actions a policy actually visits: the sum, over states, of how often that state is visited times its value, which itself breaks down into the sum over actions of how likely the policy is to take that action times the expected return of taking it.

J(θ) = Σs dπ(s) Vπ(s) = Σs dπ(s) Σa πθ(a|s) Qπ(s,a) (Q: expected future return after action a in state s)

A distinction worth being precise about: Q(s,a) (expected future return after action a in state s) is not the immediate reward for the current action. It includes the rewards obtained while continuing under the policy.

It's not necessary to differentiate d or Q (expected future return from the state-action pair) with respect to θ at all — the core idea of policy gradient is that we're estimating the gradient of the reward function directly. That's what the Policy Gradient Theorem gives us:

∇θJ(θ) = Es~dπθ, a~πθ[∇θ log πθ(a|s) · Qπθ(s,a)]

Why advantage instead of raw Q (expected future return after action a in state s)

Q (expected future return after action a in state s) can be replaced with Advantage, where Q − V means the expected return of the action minus the expected return of the state. This asks: after choosing at in st, how much better or worse was the result than the policy's average expectation in that state? Subtracting the state-dependent baseline from Q (expected future return from the state-action pair) does not change the gradient's expectation, but it reduces variance and stabilizes the loss.

gradient ≈ advantage × ∇θ log πθ(action | state),   Aπ(st,at) = Qπ(st,at) − Vπ(st) (Q: expected future return after at in st)

Example: advantage for a terminal answer

Suppose the state s contains the question “1 + 1,” and the critic predicts V(s) = 90. This means the critic expects an average future return of 90 before seeing which answer the policy chooses.

  • The model answers “2”: the episode ends with reward 100, so Q(s, “2”) (expected future return after choosing “2”) = 100.
    A(s, “2”) = Q(s, “2”) − V(s) = 100 − 90 = 10
    The action performed 10 points better than the critic expected.
  • The model answers “3”: the episode ends with reward 0, so Q(s, “3”) (expected future return after choosing “3”) = 0.
    A(s, “3”) = Q(s, “3”) − V(s) = 0 − 90 = −90
    The action performed 90 points worse than the critic expected.

This example uses terminal actions, so the final reward is the complete future return. For a nonterminal action, one-step TD estimates Q(st,at) (expected future return after at in st) with the immediate reward plus the next state's predicted value:

Q̂(st,at) = rt + γV(st+1)

Subtracting the current baseline gives the one-step advantage, which is also the TD error:

Ât(1) = Q̂(st,at) − V(st) = rt + γV(st+1) − V(st) = δt

Estimating Q (expected future return after action a in state s) the naive way — and why it's too expensive

Q(st,at) (expected future return after at in st) represents the return obtainable from the current state and action all the way to the end. The most direct way to estimate it: starting from the same prefix and token, sample many future continuations y(1)t+1:T, …, y(K)t+1:T, score each complete response with the reward model to get r(1), …, r(K), then average:

Q̂(st,at) = (1/K) Σk=1K R(k)

When K is large enough, this approaches the true Q (expected future return from the state-action pair). But the procedure is extremely expensive:

  • Every token needs many sampled continuations.
  • Every continuation needs a reward-model pass.
  • A single response may already contain thousands of tokens.

Estimating V follows the same pattern, except the current action is sampled from the policy rather than fixed:

  1. Start from state st.
  2. Sample the first token according to the policy.
  3. Continue generating a complete answer and obtain its return.
  4. Repeat M times and average the returns.

Because this computation is so expensive, PPO does not explicitly estimate Q (expected future return after the current token) this way for every token in practice.

Value function fundamentals: the Bellman Equation

The value of being in a state s under a specific policy π is the expected immediate reward plus the discounted expected value of the next state s':

Vπ(s) = Σs' T(s,π(s),s') (R(s,π(s),s') + γVπ(s'))

where s is the current state, π(s) is the action taken under policy π, T(s,a,s') is the transition probability of landing in s' after taking action a in state s, R(s,a,s') is the immediate reward received, and γ (0 ≤ γ < 1) is the discount factor determining how much future rewards are valued relative to immediate ones.

To find the best possible policy, we use the Bellman Optimality Equation. It states that the value of a state under an optimal policy must equal the expected return from the best possible action available in that state — instead of following one fixed policy π, it evaluates every possible action a ∈ A and picks whichever maximizes the sum of immediate reward and discounted downstream value:

V*(s) = maxa∈A Σs'∈S T(s,a,s') (R(s,a,s') + γV*(s'))

Temporal Difference learning: the core idea of bootstrapping

The simplest form of TD learning is TD(0). When an agent transitions from state S to a new state S', receives reward R, and uses discount factor γ, the update rule for V(S) is:

V(S) ← V(S) + α(R + γV(S') − V(S))

Here V(S) is the current estimated value of the state you just left; α is the learning rate, i.e. how much weight to give new information; R + γV(S') is the TD Target — the actual reward received plus the discounted estimated value of the state you just landed in; and (R + γV(S') − V(S)) is the TD Error, the discrepancy between your estimate before the step and your estimate after it. The goal of TD learning is simply to keep adjusting V(S) until this error shrinks toward zero.

What makes this different from Monte Carlo is worth stating plainly: TD can stop midway. rt + γrt+1 + γ²V(st+2) is a legitimate estimate because V(st+2) estimates the remaining future for you. Monte Carlo, by contrast, doesn't trust any intermediate value estimate — its return Gt = rt + γrt+1 + γ²rt+2 + … + rT requires actually walking all the way to the terminal state. In short: TD = a real portion of the future + a predicted portion of the future; MC = wait for the entire real outcome. That's what "bootstrap" means here — using a slice of real, observed experience plus the critic's own value estimate to stand in for everything not yet observed.

From TD(0) to n-step TD to GAE

Very important: this is the essence of Temporal Difference learning. The central idea is:
TD = part of the real future + a value estimate for the remaining future
This is called bootstrapping.

1-step TD: observe one real step, then bootstrap

  • 1-step return: only one future step is directly observed.
Rt(1) = rt + γV(st+1)
  • We observe what actually happens from t to t+1 and receive the real reward rt.
  • We do not wait for the rest of the trajectory to happen. Instead, V(st+1) estimates the remaining future.
  • We use this target to correct the current prediction V(st).
δt = rt + γV(st+1) − V(st)

Here δt is the TD error. The name “Temporal Difference” refers to a consistency error between value predictions at adjacent time steps.

2-step TD: observe two real steps, then bootstrap

Rt(2) = rt + γrt+1 + γ2V(st+2)
Directly observed r_t ──→ r_t+1 │ ▼ s_t+2 │ │ stop the real rollout ▼ V(s_t+2) │ ▼ estimates the entire remaining future

2-step TD = 2 steps of reality + bootstrap the rest.

n-step TD: observe n real steps, then hand off to the critic

Rt(n) = rt + γrt+1 + ⋯ + γn−1rt+n−1 + γnV(st+n)

n-step TD = n real steps + the critic's estimate for everything after that. This is also bootstrapping.

The essential difference between TD and Monte Carlo

  • TD can stop before the trajectory ends:
    rt + γrt+1 + γ2V(st+2)
    V(st+2) estimates the remaining future.
  • Monte Carlo does not use an intermediate value estimate:
    Gt = rt + γrt+1 + γ2rt+2 + ⋯ + γT−trT
    It must follow the real trajectory all the way to the terminal state.
    t ─────────────────────────────→ terminal real real real real real real

Summary: TD uses part of the real future and predicts the rest; Monte Carlo waits for the complete real outcome.

1-step TD only truly observes one step: Rt(1) = rt + γV(st+1). You know what really happened going from t to t+1 and you have rt, but rather than waiting for everything after that to actually play out, you directly trust V(st+1)'s estimate of everything remaining. 2-step TD truly observes two steps before handing off to the critic: Rt(2) = rt + γrt+1 + γ²V(st+2). The general n-step version:

Rt(n) = rt + γrt+1 + … + γn−1rt+n−1 + γnV(st+n)   =   (n steps of actual experience) + (estimate of everything remaining)

From n-step return to n-step advantage

The n-step advantage compares the n-step return with the value predicted at the current state:

Ât(n) = Rt(n) − V(st)

First, apply this definition directly to the 1-step and 2-step returns:

  1. 1-step advantage

    The 1-step return is:

    Rt(1) = rt + γV(st+1)

    Subtract the current-state baseline V(st):

    Ât(1) = Rt(1) − V(st) = rt + γV(st+1) − V(st)
  2. 2-step advantage

    The 2-step return is:

    Rt(2) = rt + γrt+1 + γ2V(st+2)

    Subtract the current-state baseline V(st):

    Ât(2) = Rt(2) − V(st) = rt + γrt+1 + γ2V(st+2) − V(st)

Connecting these advantages to TD residuals

Now define the one-step TD residual:

δt = rt + γV(st+1) − V(st)

Comparing this definition with the advantages derived above gives:

  • 1-step: Ât(1) = δt
  • 2-step: Ât(2) = δt + γδt+1
  • n-step: Ât(n) = Σl=0n−1 γlδt+l

The next derivation verifies that the 2-step advantage obtained from the return definition is identical to the 2-step advantage obtained from TD residuals.

Why the two formulas for 2-step advantage are equivalent

The two formulas being compared are:

  1. Formula 1 — derived from Ât(2) = Rt(2) − V(st):
    Ât(2) = rt + γrt+1 + γ2V(st+2) − V(st)
    This says: observe two real rewards, estimate the remaining future with V(st+2), then subtract the current baseline V(st).
  2. Formula 2 — derived from one-step TD residuals:
    Ât(2) = δt + γδt+1
    This says: add the current TD error to the discounted TD error from the next time step.

Claim: Formula 1 and Formula 2 produce exactly the same 2-step advantage.

The following expansion shows why these two formulas produce exactly the same value:

  1. Start with the TD-residual form:
    Ât(2) = δt + γδt+1
  2. Expand both residuals:
    [rt + γV(st+1) − V(st)] + γ[rt+1 + γV(st+2) − V(st+1)]
  3. The intermediate value terms cancel:
    +γV(st+1) − γV(st+1) = 0
  4. The remaining terms are exactly the two-step return minus the current-state baseline:
    Ât(2) = rt + γrt+1 + γ2V(st+2) − V(st)

Two views of the same quantity

  • TD-residual view: accumulate the discounted TD prediction errors over the next n steps.
  • n-step-return view: observe n real rewards, use V(st+n) to estimate everything after them, and subtract the current baseline V(st).

Both views produce the same n-step advantage. Because V(st+n) already summarizes the expected future from that point onward, the rollout only needs to observe n real steps before handing the rest of the estimate to the critic.

GAE takes this one step further by not committing to any single n. It has two equivalent definitions worth holding in mind together. First, as a discounted, weighted sum of one-step TD residuals:

ÂtGAE(γ,λ) = δt + γλδt+1 + (γλ)2δt+2 + ⋯ = Σl=0∞ (γλ)l δt+l

Second, as a (1−λ)-weighted average across every n-step advantage estimator at once:

ÂtGAE = (1−λ) [Ât(1) + λÂt(2) + λ2Ât(3) + ⋯] = (1−λ) Σn=1∞ λn−1 Ât(n)

λ ∈ [0, 1) is the dial that trades bias against variance. At λ = 0, GAE collapses to pure TD(0): low variance (it doesn't depend on a long chain of random future events), but high bias if the value model V(s) is wrong. At λ = 1, it collapses to pure Monte Carlo: zero bias (it uses true observed data), but extreme variance, since one unlucky random action mid-episode can swing the entire return. In practice, setting λ around 0.95 tends to land in a sweet spot: a large reduction in variance for only a small amount of added bias.

The full pipeline, in one line

Putting it together: Reward + Value →GAE Ât →PPO loss Policy update, and in parallel the same advantage becomes the critic's own regression target: Ât + Vold(st) = R̂tλ →value loss Value-model update. This maps onto two concrete training strategies. A Monte Carlo strategy scales the policy gradient using Â = γT−trT − V(st), where every single token blindly inherits the same sequence-level blame or praise, and trains the critic by minimizing MSE directly against the full empirical outcome: L = (1/T)Σt=1T (V(st) − γT−trT)². Zero bias — targets reflect the real sequence result — but extreme variance, since trajectory fluctuations heavily destabilize the gradient. A GAE strategy scales the policy gradient smoothly using ÂGAE, where the late-stage reward echo decays exponentially by (γλ)l, and trains the critic against the GAE-bootstrapped value target instead: L = (1/T)Σt=1T (V(st) − [V(st) + ÂtGAE])². Balanced variance, since intermediate critic anchors intercept noise, at the cost of some controlled bias if the critic network is still undertrained.

Why Monte Carlo is unstable for training the value model itself

It's worth being explicit that Monte Carlo and GAE aren't only used to compute the Advantage that updates the policy (the Actor) — they're also the two core ways of training the Value Model (Critic) itself, and the difference in stability there is stark.

Training the critic with pure Monte Carlo: Monte Carlo insists that the training target at every single token position must equal the true final return — say, a score of 1.0. It forces V(s1) toward 1.0, V(s50) toward 1.0, V(s99) toward 1.0, all identically. The result: as soon as the very last step is botched, the target for the entire trajectory gets dragged toward that final outcome, regardless of position. This is exactly what produces Monte Carlo's high variance as a training signal — the value model can never hold on to the memory that "things were going well earlier," because its target keeps swinging violently with every single update.

Training the critic with TD(0)/GAE: TD(0)'s target doesn't look directly at the final score at all; it only looks one step ahead, Targett = rt + γV(st+1). Consider a sequence that was tracking a strong outcome (say, value estimates hovering around 9.0) the whole way through, and then collapses to a real final score of only 1.0 at the very last step. At step 99, the training target is Target99 = r99 + V(s100) = 0 + 1.0 = 1.0 — the real outcome genuinely did get worse there, so V(s99) correctly gets pulled down toward 1.0. But at step 98, the training target is Target98 = r98 + V(s99) — and critically, at this particular round of updating, the V(s99) sitting in memory hasn't been corrected yet and is still 9.0. So step 98's target comes out to 0 + 9.0 = 9.0, and V(s98) stays completely rock-solid at 9.0, needing no downward correction in this update at all.

The point: with TD(0)/GAE, a bad ending doesn't instantly invalidate every earlier value estimate the way it does under Monte Carlo. The correction for a bad outcome only propagates backward one step at a time, across many training updates — which is exactly why bootstrapped targets are so much more stable to train against. (In practice, the value model is trained with full-prefix training: a single 100-token sequence can supply 100 separate training examples at once, using a causal mask.)

Bootstrapping a value model from scratch

The first time you train an LLM with PPO, there's no existing critic. In principle you can generate rollouts and observe the final reward directly, then treat every prefix's training target as that same terminal reward (prefix s1, s2, s3 all trained toward, say, a reward of 5) — this doesn't need an old critic to generate the target at all. So theoretically, the critic can start from random initialization and train purely off Monte Carlo returns. The only problem: this starts out with very high variance and is relatively unstable to train. So in practice, LLM RLHF prefers a warm start. Three common initialization methods:

  • A — Initialize from the reward model. Classic InstructGPT-style: V0 ← RM. The scalar head already carries a reward-related representation, which is a natural choice inside classic RLHF. A reward model appearing to "output one value per rollout" usually isn't because its head can only output one value — in a common causal-LM reward model, the same scalar head can actually act on every token's hidden state; the reward model just conventionally uses only the last valid token's scalar as the reward for the whole response.
  • B — SFT/Policy backbone + a new value head. Split the SFT model into the part you keep (the transformer body) and the part you don't (the LM head WLM: Rd → R|V|, which produces a vocabulary distribution — not what a critic needs). The critic doesn't need p(token1), p(token2), …; it needs a scalar, V(st). So swap the LM head for a new value head wV: Rd → R, randomly initialized: V0 = TransformerθSFT + RandomLinear(d, 1). The same SFT checkpoint then branches into a policy path (transformer → LM head → vocab logits) and a critic path (the same transformer → a fresh random value head → per-token scalars V1…VT).
  • C — Dedicated warm-up of the critic first. Fix the policy at πSFT, generate a large number of rollouts, get the actual return Gt for each, then pretrain: minψ Σt (Vψ(st) − Gt)², giving V0. Only after that does formal joint actor+critic training begin. The idea is easy to follow: before formal PPO starts, first let the critic learn a basically reliable return predictor.
